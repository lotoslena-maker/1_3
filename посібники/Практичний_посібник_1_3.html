Тема 1 Заняття 3

Для слухачів, які вперше працюють із Git, GitHub, Visual Studio Code, Python і PostgreSQL у Windows.

Мета заняття — підготувати робоче середовище, створити власний репозиторій, виконати Python та SQL і зберегти результати в історії Git. Виконуйте розділи послідовно. Після кожного етапу перевіряйте зазначений результат.

Навчальні питання

1. Основи використання систем контролю версій засобів ІАС.

2. Основи використання інтегрованих середовищ розробника засобів ІАС.

Посібник деталізує практику з файлу practice3.ipynb. У вихідному завданні наведено різні приклади назви репозиторію; тут послідовно використано iaz-practicals. Папку заняття названо 1.3 відповідно до завдання.

1 Що саме ми встановлюємо

Git — програма на комп’ютері, яка зберігає історію змін файлів. GitHub — сайт для розміщення репозиторіїв і спільної роботи. Обліковий запис GitHub створюють у браузері; встановлювати GitHub Desktop для цього заняття не потрібно.

Visual Studio Code, або VS Code, — редактор коду. Розширення додають підтримку Python, баз даних та інших інструментів. Інтегроване середовище поєднує редагування, запуск, налагодження і контроль версій в одному робочому вікні.

Python — інтерпретатор, який виконує файл check.py. Розширення Python у VS Code допомагає працювати з кодом, але сам інтерпретатор встановлюється окремо.

PostgreSQL — сервер баз даних. Після встановлення у Windows він працює як служба, навіть коли VS Code закрито. psql — консольний клієнт цього сервера; pgAdmin — графічний клієнт. Розширення PostgreSQL у VS Code — ще один клієнт. Встановлення розширення саме по собі не встановлює сервер.

Послідовність роботи: встановити програми у Windows → створити репозиторій на GitHub → клонувати його на комп’ютер → відкрити папку у VS Code → створити й виконати файли → зробити commit → виконати push → перевірити GitHub.

2 Підготовка Windows та місця для роботи

1. Основний маршрут розраховано на Windows 11 x64. Відкрийте Пуск → Параметри → Система → Про систему та перевірте тип системи. На ARM64 набір установників погодьте з викладачем; x64 і ARM64 — різні архітектури.

2. Переконайтеся, що є доступ до Інтернету, електронної пошти та достатньо місця на диску. Для встановлення PostgreSQL потрібні права адміністратора. На навчальному комп’ютері підготовку служби виконує адміністратор або викладач.

3. У Провіднику увімкніть Вигляд → Показати → Розширення імен файлів. Це допоможе уникнути назви check.py.txt.

4. Створіть папку для своїх проєктів, наприклад C:\IAZ_Labs. У командах цього посібника використовується лише C:\IAZ_Labs. Якщо немає прав на C:\, створіть IAZ_Labs у власних Документах і використовуйте цей шлях.

5. Програми залишайте у стандартних каталогах установників. Робочі файли зберігайте в папці проєктів, а не в Program Files і не в каталозі даних PostgreSQL. Файли установників у Завантаженнях ще не означають, що програми встановлено.

6. Завантажуйте продукти за офіційними адресами з розділу 15. На всій групі бажано використовувати узгоджені стабільні версії. Не обирайте beta, preview або RC.

Як вводити команди: відкрийте Пуск, введіть PowerShell і запустіть звичайне вікно. Пізніше використовуйте Terminal → New Terminal у VS Code. Команди вводьте по одному рядку та натискайте Enter. Не копіюйте позначення запрошення PS C:\…>. Приклади нижче призначені для PowerShell; SQL запускається окремо у клієнті бази даних.

3 Встановлення VS Code у Windows

1. Відкрийте https://code.visualstudio.com/download. Оберіть Windows та User Installer для своєї архітектури. Не плутайте Visual Studio Code з Visual Studio.

2. Запустіть завантажений установник. Прийміть ліцензію, залиште типовий каталог користувача. User Installer зазвичай не потребує прав адміністратора; для всіх користувачів адміністратор може обрати System Installer.

3. У додаткових параметрах увімкніть Add to PATH. Якщо доступні, увімкніть пункти Open with Code для папок і файлів та реєстрацію редактора для підтримуваних типів файлів.

4. Натисніть Install, потім Finish. Запустіть VS Code. Закрийте старі вікна термінала і відкрийте нове, щоб воно отримало оновлений PATH.

5. Перевірте у PowerShell:

code --version

Очікувано: номер версії та технічні відомості. Якщо команда не знайдена, спробуйте перезапуск VS Code; відкривати проєкт також можна через File → Open Folder без цієї команди.

Назви меню наведено англійською. За бажанням відкрийте Extensions клавішами Ctrl+Shift+X, знайдіть Ukrainian Language Pack від Microsoft, встановіть і перезапустіть редактор. Розташування та назви окремих кнопок можуть відрізнятися між версіями.

4 Встановлення Git та створення облікового запису GitHub

4.1 Git for Windows

1. Відкрийте https://git-scm.com/install/win. Завантажте звичайний установник Git for Windows для своєї архітектури.

2. Запустіть установник і залиште типовий каталог. Для редактора Git можна вибрати Visual Studio Code, оскільки він уже встановлений.

3. На екрані PATH оберіть Git from the command line and also from 3rd-party software. Це дає змогу VS Code і PowerShell знаходити Git.

4. Якщо установник пропонує назву початкової гілки, задайте main. Залиште типовий Git Credential Manager для входу в GitHub. Решту параметрів для цього заняття залиште типовими.

5. Завершіть установлення, повністю закрийте й знову відкрийте VS Code та термінал. Перевірте:

git --version

Очікувано: git version з номером. Далі налаштуйте автора комітів. У прикладі замініть ім’я та адресу на власні; лапки залиште.

git config --global user.name "Ваше ім’я"
git config --global user.email "your-address@example.com"
git config --global init.defaultBranch main
git config --global --get user.name
git config --global --get user.email

Ці параметри задають авторство змін, а не виконують вхід у GitHub. Можна використати приватну noreply-адресу зі сторінки GitHub Settings → Emails. На спільному комп’ютері перевірте, що не залишили дані попереднього слухача.

4.2 GitHub у браузері

1. Відкрийте https://github.com, натисніть Sign up, укажіть власну пошту, пароль і ім’я користувача, виконайте підтвердження адреси. Якщо обліковий запис уже є, натисніть Sign in.

2. Збережіть дані входу у власному менеджері паролів. Якщо налаштовуєте двофакторний захист, збережіть коди відновлення.

3. Для навчання достатньо безкоштовного облікового запису. Підписка GitHub Copilot, платний тариф і GitHub Desktop для виконання цієї практики не потрібні.

Результат етапу: Git працює у PowerShell, ім’я та пошта автора перевірені, сторінка GitHub відкрита під вашим обліковим записом.

5 Встановлення Python та розширень VS Code

5.1 Інтерпретатор Python

Для вихідної практики потрібен Python 3.11 або новіший. Оберіть погоджену викладачем стабільну версію; наведений скрипт не потребує сторонніх бібліотек.

1. Відкрийте https://www.python.org/downloads/windows/. Основний сучасний спосіб — Python install manager. Завантажте його з python.org або через посилання Microsoft Store на офіційній сторінці.

2. Для MSIX відкрийте файл і натисніть Install. Якщо встановлення через Store або MSIX обмежено політикою закладу, зверніться до адміністратора або скористайтеся звичайним Windows installer для погодженої версії Python.

3. Відкрийте новий PowerShell після встановлення менеджера. Команда python --version має показати версію; якщо потрібне початкове встановлення інтерпретатора, виконайте python, дочекайтеся встановлення та появи >>>. Введіть exit(), щоб повернутися до PowerShell. За допомогою py list можна переглянути інтерпретатори сучасного менеджера.

4. Альтернативний звичайний EXE-установник: виберіть Windows installer (64-bit), не embeddable package. На першому екрані позначте Add python.exe to PATH, далі Install Now. Ця галочка стосується EXE-установника; у менеджера інший інтерфейс. Не встановлюйте обидва способи без потреби.

5. Перевірте у новому терміналі:

python --version
python -m pip --version
python -c "print('Python OK')"

Очікувано: Python 3.11 або новіший, відомості про pip та рядок Python OK. Якщо працює тільки py, можна використати py --version і py -m venv .venv у розділі 10. Не вводьте команди PowerShell у запрошенні Python >>>.

5.2 Розширення редактора

1. У VS Code натисніть Ctrl+Shift+X.

2. Знайдіть Python від Microsoft, ідентифікатор ms-python.python, та натисніть Install. Якщо VS Code пропонує довіряти видавцю, перевірте Microsoft. Допоміжні рекомендовані компоненти Python можуть встановитися разом із ним.

3. Знайдіть PostgreSQL від Microsoft, ідентифікатор ms-ossdata.vscode-pgsql, і встановіть його. Саме цей ідентифікатор відрізняє потрібне розширення від інших схожих.

4. Для читання вихідного practice3.ipynb у VS Code встановіть Jupyter від Microsoft, ms-toolsai.jupyter. Якщо потрібно лише переглянути інструкцію, не запускайте клітинки і не обирайте ядро. Для файлу check.py Jupyter не потрібен.

Результат: Python працює поза VS Code, а потрібні розширення позначені як встановлені. Підключення PostgreSQL виконаємо після встановлення сервера.

6 Встановлення сервера PostgreSQL у Windows

6.1 Завантаження та проходження майстра

1. Відкрийте https://www.postgresql.org/download/windows/ і перейдіть за Download the installer на сайт EDB. Для цієї практики можна обрати стабільну підтримувану PostgreSQL 17.x або іншу версію, погоджену для групи. Запишіть її номер. Не завантажуйте пробні корпоративні продукти замість звичайного PostgreSQL.

2. Завантажте Windows x86-64 installer для комп’ютера x64. Запустіть його; підтвердьте запит Windows на права адміністратора.

3. Installation Directory: залиште типовий каталог на зразок C:\Program Files\PostgreSQL\17. Число залежить від обраної версії. Не встановлюйте сервер у папку репозиторію.

4. Select Components: потрібні PostgreSQL Server і Command Line Tools. pgAdmin 4 можна встановити для графічного доступу. Залежно від версії установника pgAdmin входить до переліку компонентів або пропонується для окремого завантаження. Для маршруту через VS Code та psql pgAdmin не обов’язковий.

5. Data Directory: залиште запропонований каталог даних, наприклад C:\Program Files\PostgreSQL\17\data. Тут сервер зберігає бази даних; не копіюйте сюди навчальні SQL-файли та не додавайте цей каталог до Git.

6. Password: створіть і двічі введіть пароль користувача бази даних postgres. Збережіть його приватно. Це окремий пароль PostgreSQL, він не є паролем Windows або GitHub. Надалі у VS Code і psql потрібен саме він.

7. Port: залиште 5432. Якщо порт уже зайнятий, з’ясуйте з викладачем, чи встановлено PostgreSQL раніше. Якщо погоджено інший порт, наприклад 5433, запишіть його та використовуйте у всіх підключеннях.

8. Locale: залиште типовий варіант, якщо викладач не задав іншого. Перегляньте підсумок, натисніть Next, дочекайтеся завершення.

9. На завершенні зніміть запуск Stack Builder, якщо він пропонується. Додаткові драйвери, PostGIS та інші пакети для цього заняття не потрібні.

Не перевстановлюйте сервер лише тому, що psql не знайдено у терміналі. Спочатку перевірте службу та PATH. Наявний робочий сервер можна використати з дозволу викладача.

6.2 Перевірка служби та клієнта

Натисніть Win+R, введіть services.msc і натисніть Enter. Знайдіть службу з назвою на зразок postgresql-x64-17. Стан має бути Running або Виконується. Якщо вона зупинена, запуск може вимагати прав адміністратора.

У новому PowerShell виконайте:

psql --version

Якщо команда не знайдена, для версії 17 перевірте повний шлях:

& "C:\Program Files\PostgreSQL\17\bin\psql.exe" --version

Символ & потрібний у PowerShell для запуску програми за шляхом у лапках. Для іншої версії замініть 17 на фактичний номер каталогу.

Щоб надалі працювала коротка команда psql, відкрийте пошук Windows → Змінення змінних середовища для облікового запису → Змінні середовища → змінна користувача Path → Змінити → Створити. Додайте C:\Program Files\PostgreSQL\17\bin як новий запис. Не замінюйте і не видаляйте наявні записи Path. Підтвердьте зміни й перезапустіть VS Code та термінали.

Версія psql перевіряє лише наявність клієнта. Доступність сервера перевіряє реальне підключення:

psql -h localhost -p 5432 -U postgres -d postgres

Якщо коротка команда ще не працює, використайте повний шлях до psql.exe з тими самими параметрами. На запит Password введіть пароль PostgreSQL; під час набору символи можуть не відображатися. Натисніть Enter.

У запрошенні postgres=# виконайте SQL:

SELECT current_database(), current_user;

Очікувано: база postgres і користувач postgres. Для виходу з psql введіть \q та Enter. Крапка з комою завершує SQL-запит; команда \q її не потребує.

7 Створення репозиторію GitHub та локальної копії

1. У браузері GitHub натисніть + → New repository. Назва: iaz-practicals. Опис: Практичні роботи з ІАЗ.

2. Оберіть Private, якщо викладач не вимагає іншого. Увімкніть Add README та натисніть Create repository. Наявний README створить початкову гілку й коміт. Якщо викладач має перевіряти приватний репозиторій, надайте йому доступ узгодженим способом.

3. На сторінці репозиторію натисніть Code → HTTPS → скопіюйте адресу. Вона матиме вигляд https://github.com/ВАШ_ЛОГІН/iaz-practicals.git. Використайте скопійовану власну адресу, а не буквальний текст ВАШ_ЛОГІН.

4. У VS Code натисніть Ctrl+Shift+P, введіть Git: Clone, виберіть команду і вставте адресу. На запит папки оберіть C:\IAZ_Labs. Git створить у ній підпапку iaz-practicals. Не створюйте вкладений репозиторій ще раз.

5. Якщо відкривається браузер для входу, увійдіть до свого GitHub і підтвердьте вхід Git Credential Manager або VS Code. Для HTTPS звичайний пароль GitHub не вводять як пароль Git. Якщо автоматичний вхід не спрацьовує, зверніться до викладача; не записуйте токени у файли проєкту.

6. Після клонування натисніть Open. Довіряйте робочій папці лише коли це ваш репозиторій або перевірені матеріали викладача.

Альтернатива через PowerShell: перейдіть до C:\IAZ_Labs командою Set-Location, виконайте git clone зі своєю HTTPS-адресою, потім у VS Code File → Open Folder відкрийте C:\IAZ_Labs\iaz-practicals. Виконуйте лише один спосіб клонування.

Перевірка у Terminal → New Terminal:

Get-Location
git remote -v
git status

Очікувано: поточна папка закінчується на iaz-practicals; origin веде до вашого GitHub; статус показує гілку і чисту робочу папку. Назву поточної гілки можна перевірити командою git branch --show-current. Не виконуйте git init усередині вже клонованої папки.

8 Перші дії у VS Code

Explorer, Ctrl+Shift+E — дерево папок і файлів ліворуч. Редактор — центральна область, де змінюють текст. Terminal → New Terminal — нижня панель для команд. Source Control, Ctrl+Shift+G — зміни Git. Extensions, Ctrl+Shift+X — розширення. Command Palette, Ctrl+Shift+P — пошук команд редактора.

1. Переконайтеся, що в Explorer відкрита папка iaz-practicals, а не лише окремий файл.

2. Правою кнопкою на корені проєкту → New Folder → введіть 1.3. Усередині неї через New File створіть README.md, .gitignore, check.py та schema.sql. Крапка перед gitignore є частиною назви.

3. Відкрийте файл, вставте відповідний текст із розділу 9 та збережіть Ctrl+S. Крапка на вкладці зазвичай означає незбережені зміни.

11 Підключення PostgreSQL у VS Code та виконання SQL

11.1 Створення підключення

1. Переконайтеся, що служба PostgreSQL запущена, а розширення ms-ossdata.vscode-pgsql встановлено.

2. Відкрийте панель PostgreSQL через її значок ліворуч або Ctrl+Alt+D. У Connections натисніть + чи Add New Connection.

3. Введіть параметри: Server name — localhost; Port — 5432 або порт вашого встановлення; Authentication Type — Password; User name — postgres; Password — ваш пароль PostgreSQL; Database name — postgres; Connection Name — Local PostgreSQL.

4. Для власного комп’ютера можна зберегти пароль у сховищі облікових даних розширення. На спільному комп’ютері не обирайте Save Password. Не вставляйте пароль у README, schema.sql, скриншоти чи Git.

5. Натисніть Save & Connect. Очікувано: підключення у дереві Connections зі станом успішного з’єднання. Для локального сервера не потрібні обліковий запис Azure, платна хмара чи підписка Copilot.

Якщо з’являється вимога SSL, перевірте додаткові параметри підключення. Для навчального локального localhost допускається вимкнений SSL, якщо сервер його не налаштований використовувати. Для віддалених серверів параметри захисту задає адміністратор; не переносіть локальне налаштування автоматично.

11.2 Окрема навчальна база

Правою кнопкою на підключенні → New Query. Переконайтеся, що обрана база postgres. Виконайте лише одну команду:

CREATE DATABASE iaz_lab;

У цьому розширенні запуск запиту — Ctrl+Shift+E або кнопка виконання у редакторі запитів. Виконуйте команду в підключеному SQL-редакторі: в іншій панелі така комбінація може відкривати Explorer. CREATE DATABASE запускайте окремо, поза явною транзакцією BEGIN.

Створення бази виконується один раз. Якщо бачите database already exists, не видаляйте базу: перейдіть до підключення. Оновіть дерево через Refresh. У списку баз редактора запитів оберіть iaz_lab або через палітру виконайте Change PostgreSQL Database. Якщо зручніше, створіть друге підключення з тими самими параметрами та Database name = iaz_lab.

Перед створенням таблиці виконайте:

SELECT current_database();

Очікувано: iaz_lab. Це перевірка, що таблиця з’явиться саме у навчальній базі.

11.3 Виконання schema.sql

Відкрийте збережений 1.3/schema.sql. Якщо файл ще не пов’язаний із підключенням, відкрийте New Query для iaz_lab і скопіюйте в нього вміст schema.sql. Виконайте запит кнопкою запуску або Ctrl+Shift+E. Очікувано: повідомлення про успішне CREATE TABLE; при повторі можлива примітка, що таблиця вже існує.

Перевірте створення таблиці окремим запитом:

SELECT id, name FROM public.test_data;

Очікувано: стовпці id і name та 0 рядків, якщо таблиця щойно створена. Порожній результат без помилки означає успіх: схема ще не додає даних.

11.4 Додаткова перевірка даних

Для перевірки запису та читання виконайте окремо такий блок. Ця вправа доповнює мінімальну практику і не потребує зміни schema.sql:

INSERT INTO public.test_data (name)
SELECT 'Навчальний запис'
WHERE NOT EXISTS (
    SELECT 1 FROM public.test_data
    WHERE name = 'Навчальний запис'
);

SELECT id, name FROM public.test_data ORDER BY id;

У новій базі очікувано один рядок із текстом Навчальний запис. Повторний послідовний запуск цього блоку не додає ще одного такого запису. Значення id не обов’язково дорівнює 1 після попередніх спроб; перевіряйте текст і кількість рядків.

Використання postgres як адміністратора тут обмежене локальною навчальною вправою. Для реальних застосунків адміністратор створює окремі облікові записи з необхідними правами.

11.5 Запасний маршрут через psql

Якщо розширення тимчасово недоступне, після створення iaz_lab відкрийте PowerShell у корені репозиторію та виконайте:

psql -h localhost -p 5432 -U postgres -d iaz_lab -v ON_ERROR_STOP=1 -f .\1.3\schema.sql
psql -h localhost -p 5432 -U postgres -d iaz_lab -c "SELECT id, name FROM public.test_data;"

Для створення бази через psql можна спочатку підключитися до postgres як у розділі 6, виконати CREATE DATABASE iaz_lab; та вийти через \q. Якщо psql не знайдено, використайте повний шлях до psql.exe. Параметр -f передає файл на виконання серверу. SQL не потрібно вводити прямо у PowerShell як окрему команду.

Запишіть у README: назву бази iaz_lab, факт створення test_data та фактичний результат запиту. Зберігання SQL у Git не зберігає саму базу або її рядки: до репозиторію потрапляє текст інструкцій.

12 Збереження роботи через Git у VS Code

Збереження Ctrl+S записує файл на диск. Stage готує вибрані зміни до коміту. Commit створює локальний знімок змін. Push надсилає коміти до GitHub. Clone створює локальну копію репозиторію; pull отримує віддалені зміни. Коміт може існувати без Інтернету, але push потребує зв’язку з GitHub.

1. Збережіть усі чотири файли та внесіть фактичні результати у 1.3/README.md.

2. Відкрийте Source Control, Ctrl+Shift+G. Натисніть на check.py, щоб переглянути різницю. Нові файли можуть мати позначку U, змінені — M; це стани Git, а не помилки.

3. Переконайтеся, що серед змін немає .venv, паролів або службових даних. Натисніть + біля потрібних файлів або Changes → Stage All Changes, якщо весь перелік перевірений. Чотири файли папки 1.3 мають перейти у Staged Changes.

4. У полі повідомлення введіть Add 1.3 initial lab files. Натисніть Commit. Якщо редактор просить налаштувати ім’я та пошту, виконайте команди розділу 4 і повторіть.

5. Відкрийте меню … у Source Control → Push. Якщо запропоновано Publish Branch для нової гілки, перевірте репозиторій і опублікуйте її. Для клонованої типової гілки зазвичай достатньо Push.

6. За потреби завершіть вхід у браузері GitHub. Не використовуйте Force Push. Якщо замість Push обираєте Sync Changes, враховуйте, що синхронізація може як отримати, так і надіслати зміни.

7. Відкрийте власний репозиторій у браузері й оновіть сторінку. У потрібній гілці відкрийте 1.3 та перевірте README.md, .gitignore, check.py, schema.sql. У списку комітів має бути ваше повідомлення.

Еквівалент для відпрацювання у терміналі з кореня репозиторію:

git status
git add 1.3/README.md 1.3/.gitignore 1.3/check.py 1.3/schema.sql
git commit -m "Add 1.3 initial lab files"
git push
git status
git log -3 --oneline

Якщо коміт уже зроблено кнопкою, повторювати його командою не потрібно: повідомлення nothing to commit є нормальним. Після успішного push git status має показувати чисту робочу папку та узгодженість з origin для гілки, яка його відстежує.

Додаткова вправа для історії: допишіть у README одне речення про призначення Git, збережіть, перегляньте різницю, зробіть другий коміт із повідомленням Update 1.3 learning results і знову виконайте push. Переконайтеся у GitHub, що видно обидва ваші коміти.

13 Типові труднощі та способи перевірки

Команда git або code не знайдена

Закрийте всі вікна VS Code і PowerShell та відкрийте знову. Перевірте, чи встановлена програма, а не лише завантажений установник. Для Git перевірте вибір PATH в установнику. Для VS Code можна тимчасово використовувати File → Open Folder.

Python відкриває Store або показує іншу версію

Перевірте python --version і py --version. Якщо встановлено Python install manager, перегляньте py list. У Windows у розділі керування псевдонімами виконання застосунків перевірте, який Python пов’язаний із командою; не вимикайте всі псевдоніми навмання, оскільки менеджер Python також використовує їх. У VS Code повторіть Python: Select Interpreter і використайте прямий шлях до .venv\Scripts\python.exe.

Python не знаходить check.py

Виконайте Get-Location. Команда python 1.3/check.py призначена для кореня репозиторію. Якщо термінал уже всередині 1.3, шлях до скрипту — check.py. Перевірте назву у Провіднику та відсутність .txt. Збережіть файл Ctrl+S.

PostgreSQL показує connection refused

Перевірте службу у services.msc, адресу localhost та фактичний порт. Додатково в PowerShell виконайте Test-NetConnection localhost -Port 5432. TcpTestSucceeded = True означає доступність TCP-порту, але ще не підтверджує пароль чи правильну базу. Не відкривайте порт у мережу і не вимикайте брандмауер для локальної вправи.

Password authentication failed

Уведіть саме пароль користувача postgres, заданий при встановленні, і перевірте розкладку клавіатури. Пароль GitHub тут не підходить. Якщо пароль забутий, зверніться до адміністратора для контрольованого відновлення; не перемикайте автентифікацію сервера на trust.

psql працює лише за повним шляхом

Сервер перевстановлювати не потрібно. Додайте фактичний каталог bin PostgreSQL до Path користувача, не змінюючи решту записів, та відкрийте новий термінал. psql --version і успішне з’єднання — дві окремі перевірки.

Database already exists або relation does not exist

Якщо база iaz_lab існує, перейдіть до неї та не повторюйте CREATE DATABASE. Якщо таблицю не знайдено, виконайте SELECT current_database(); і перевірте, що результат iaz_lab. Потім виконайте schema.sql саме в цій базі. Для оновлення дерева використайте Refresh.

У Git видно сотні файлів .venv

Перевірте, що .gitignore збережений без розширення .txt, а середовище розташоване у 1.3/.venv. Якщо файли лише підготовлено до коміту, виберіть Unstage Changes і перевірте ігнорування командою git check-ignore -v 1.3/.venv/pyvenv.cfg. Правила .gitignore не вилучають уже відстежувані файли: їх очищення з індексу узгодьте з викладачем, не видаляйте саме середовище навмання.

GitHub не показує файли або відхиляє push

Перевірте git remote -v, поточну гілку та те, чи був push після commit. У браузері відкрийте ту саму гілку. При відмові в доступі перевірте обліковий запис і права на репозиторій. Повідомлення non-fast-forward означає, що на GitHub є нові зміни; не використовуйте Force Push. Збережіть локальну роботу та з викладачем отримайте віддалені зміни й узгодьте їх.

Встановлення PostgreSQL переривається

Збережіть текст помилки. Перевірте права адміністратора та наявність попередньої служби. EDB попереджає про можливі обмеження не-ASCII символів в іменах користувачів, комп’ютера або шляхах. Якщо помилка пов’язана з цим, адміністратор підготує відповідний обліковий запис чи каталог. Не перейменовуйте власноруч системну папку профілю Windows і не видаляйте існуючі бази.

Для підтвердження можна зробити скриншоти термінала, SQL-результату та сторінки GitHub. Не включайте паролі або токени. Базу даних, .venv та встановлені програми передавати через GitHub не потрібно.

Контрольні запитання: чим відрізняються Git і GitHub; чим відрізняються Ctrl+S, commit та push; навіщо потрібен .gitignore; чому розширення Python не замінює Python; чому розширення PostgreSQL не замінює сервер; як перевірити, до якої бази підключено SQL-редактор?

Для викладача: до заняття перевірте права встановлення, доступ до сайтів, єдині версії продуктів і готовність служби PostgreSQL. Встановлення краще виконати заздалегідь або виділити окремий підготовчий час. На практиці послідовно приймайте чотири результати: інструменти працюють → Python виконується → SQL виконується → файли та коміт видно в GitHub.
